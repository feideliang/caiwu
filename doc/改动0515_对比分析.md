# 改动0515 vs 当前系统 vs Plan 对比分析（修订版）

> 目标：对照 `doc\改动0515.docx` 中 5.1～5.9 的改动点，校正原对比分析中的过时判断，补齐遗漏需求、风险和落地说明。  
> 范围：本文件只做需求/现状/实施差距分析，不改代码。

---

## 一、总体结论

`改动0515` 共 9 个主要改动项。当前系统不是“完全未覆盖”，而是存在大量**局部实现但口径不一致**的问题：总览驾驶舱、核心盈利能力、结构健康度、负毛利指标、变动分析页面等已经有雏形；真正的风险集中在**期间语义、毛利率拆解公式、存续/新增/退出分类、季度/年累计聚合、展示格式统一**。

| 章节 | 改动要求摘要 | 当前系统现状（静态检查） | Plan/实现缺口 |
|---|---|---|---|
| 5.1 毛利率变动因素拆解 | 区分存续/新增/退出；新增/退出基准毛利率按整体毛利率赋值；输出结构/毛利/新增/退出影响 | `metrics_service.py` 已输出 `margin_change_analysis`，但未显式分类，新增/退出按 0 收入参与，公式仍用旧口径 | 需重做算法与输出结构 |
| 5.2 总览驾驶舱 | 4 个 KPI、核心盈利能力、结构健康度 Top10、负毛利指标、月度趋势前一年 1 月至今 + 毛利率次轴 | 4 KPI/核心盈利能力/Top10/负毛利已有雏形；期间筛选和趋势口径不符合，KPI 趋势后缀未完整透传 | 部分完成，需修期间和图表口径 |
| 5.3 变动分析 | 收入/毛利额加基期和主要变动影响；毛利率变动从 2 卡扩展为存续结构/存续毛利/新增/退出 4 卡 | `CoreMetricsPage.vue` 已有当期/基期/变化/主要变动影响；毛利率仍是当期/基期/变化/结构/毛利 5 卡，未按 4 类汇总 | 页面与算法都需调整 |
| 5.4 趋势分析 | 季度横坐标；选择部门/产品线时图例展示不同线 | 有趋势页和维度选择；`weekly` 被当成季度/周混用，图表按指标线展示，未充分使用 `dimension_trend_series` 做多维图例 | 需统一季度语义并改多维序列 |
| 5.5 部门分析 | 毛利额旁加毛利率；支持季度和年累计筛选 | 明细表已有毛利率；图表仍主要是收入/毛利额 grouped-bar；季度/年累计筛选前端看似有，后端实际聚合不对 | 需补季度/YTD真实聚合 |
| 5.6 产品分析 | 同 5.5 | 明细表已有毛利率，产品钻取已有雏形；季度/年累计同样不准，负毛利产品列复用了订单字段命名 | 需修聚合与字段语义 |
| 5.7 影响度算法修正 | 结构影响 = `(w1-w0)*(g1-g0公司)`；毛利率影响 = `w0*(g1-g0)` | 当前公式仍是 `(w1-w0)*g0` 和 `w1*(g1-g0)`；AI 知识库也写旧公式 | 必须统一后端、前端、AI 规则 |
| 5.8 数字格式 | 元/万元整数+千分位；亿元两位+千分位；百分比两位 | 只有 `toWan()`、`formatWan()`；`formatWan()`实际按“元转万元”且保留两位，小数/单位规则未统一 | 需新增统一格式化函数 |
| 5.9 加客户分析 | 新增客户分析入口和客户维度分析 | 后端支持 customer 维度和 Top10 客户；没有独立客户分析路由/页面/菜单 | Plan 仍需落地成页面 |

## 二、必须优先修正的共性问题

### 1. 期间维度语义混乱

多个页面把 `weekly` 显示成“季度”，但后端 `metrics_service.py` 和 `dashboard.py` 又把 `weekly` 当“周/日拆分”处理：

- `DashboardPage.vue`：`weekly` 标签为“季度”，但会生成周选项或月范围。
- `CoreMetricsPage.vue` / `DepartmentAnalysisPage.vue` / `ProductAnalysisPage.vue`：`weekly` 生成 `YYYY-Qn`，再转成季度末月份传给后端。
- `metrics_service.py`：`period_dimension == "weekly"` 时把月度数据近似拆成 7 天。
- `yearly` 标签显示“年累计”，但选项只有 `2026年`，不是文档要求的 `2026年1月、2026年2月...`（累计到该月）。

**修正建议：**

| 业务模式 | 前端值 | 选项示例 | 后端聚合口径 |
|---|---|---|---|
| 月度 | `monthly` | `2026年3月` | 单月 |
| 季度 | `quarterly` | `2026年Q1` | Q1 三个月合计 |
| 年累计 | `cumulative` | `2026年3月` 或 `2026年累计至3月` | 当年 1 月至所选月累计 |
| 自定义 | `custom` | 起止月份 | 起止月份合计 |

> 不建议继续用 `weekly` 表示季度；会持续造成图表、同比、环比和 AI 上下文全部错口径。

### 2. 变动分析的基期口径不统一

`CoreMetricsPage.vue` 用 `basePeriod` 单独取基期数据，但后端 `margin_change_analysis` 里的 `compare_period` 仍由 `metrics_service.py` 自己推断（上一期或去年），没有接收前端 `compareBase`。这会导致：

- 收入/毛利额卡片基期是前端计算的基期；
- 毛利率结构/毛利影响可能是后端另一个基期；
- 用户切换同比/环比后，部分卡片变了，拆解明细不一定同步。

**修正建议：**

- `getCoreMetrics()` 参数增加 `compare_period` 或 `compare_base`，后端统一按该基期计算。
- 响应返回 `current_period`、`base_period`、`compare_type`，前端不再自行猜。
- 自定义期间必须返回当前区间、基期区间的聚合结果。

### 3. 金额单位和百分比显示不一致

当前 `frontend\src\utils\format.ts` 只有：

- `toWan(value)`：元转万元，返回数字；
- `formatWan(value)`：注释写“万元”，实际又除以 10000，保留两位。

页面中仍存在 `toWan(...).toLocaleString()`、`formatMargin()`、图表内手动 `/10000` 等多套逻辑。5.8 要求应收敛为统一工具：

| 类型 | 规则 | 建议函数 |
|---|---|---|
| 元 | 整数 + 千分位 | `formatYuan(value)` |
| 万元 | 整数 + 千分位（如文档确认需整数） | `formatWan(value, { decimals: 0 })` |
| 亿元 | 两位小数 + 千分位 | `formatYi(value, { decimals: 2 })` |
| 百分比 | 两位小数 | `formatPercent(value, { suffix: '%' })` |
| 百分点 | 两位小数 + `pp` | `formatPp(value)` |

## 三、核心算法差距

### 5.1 / 5.7 毛利率变动拆解

#### 文档要求

1. 维度值分为：
   - **存续**：基期、当期都有收入；
   - **新增**：基期收入为 0，当期有收入；
   - **退出**：基期有收入，当期收入为 0。
2. 存续项拆为：
   - **存续结构影响**
   - **存续毛利率影响**
3. 新增/退出项单独汇总为：
   - **新增影响**
   - **退出影响**
4. 新增/退出没有自身基期或当期毛利率时，应按整体毛利率赋值，避免除零并保持整体变动可解释。
5. 影响度公式按 5.7 修正：
   - `结构影响 = (w1 - w0) * (g1 - G0)`
   - `毛利率影响 = w0 * (g1 - g0)`
   - 其中 `w0/w1` 为维度收入占比，`g0/g1` 为维度毛利率，`G0` 为公司基期整体毛利率。

#### 当前实现

`backend\app\services\metrics_service.py` 当前算法：

```text
structure_impact = (c_share - p_share) * p_gm / 100
margin_impact    = c_share * (c_gm - p_gm) / 100
```

问题：

- 未输出 `category = 存续/新增/退出`；
- 新增/退出维度按 0 毛利率进入公式，业务解释会失真；
- 结构影响、毛利率影响与 5.7 公式不一致；
- AI 知识库 `backend\app\api\ai.py` 也写着旧公式，会让智能助手解释与报表不一致；
- 前端 `MarginChangeItem` 类型没有分类字段，也没有新增/退出汇总字段。

#### 建议响应结构

```json
{
  "margin_change_summary": {
    "current_margin": 25.92,
    "base_margin": 26.00,
    "margin_change_pp": -0.08,
    "continuing_structure_impact": -0.01,
    "continuing_margin_impact": 0.01,
    "new_customer_or_product_impact": -0.05,
    "exit_customer_or_product_impact": -0.03
  },
  "margin_change_analysis": [
    {
      "dimension_value": "产品线A",
      "category": "continuing",
      "current_revenue": 1500000,
      "base_revenue": 1000000,
      "current_share": 25.0,
      "base_share": 29.0,
      "current_margin": 42.0,
      "base_margin": 40.0,
      "structure_impact": -0.01,
      "margin_impact": 0.57,
      "total_impact": 0.56
    }
  ]
}
```

#### 落地文件

| 文件 | 改动 |
|---|---|
| `backend\app\services\metrics_service.py` | 重写 `margin_change_analysis`，接收统一基期，分类并汇总 4 类影响 |
| `backend\app\schemas\metrics.py` | 增加分类字段和汇总 schema |
| `frontend\src\types\metrics.ts` | 同步 `MarginChangeItem` 与 summary 类型 |
| `frontend\src\views\CoreMetricsPage.vue` | 毛利率变动卡改成 4 卡：存续结构/存续毛利/新增/退出 |
| `backend\app\api\ai.py` | 知识库公式同步 5.7，避免 AI 解释旧口径 |

### 5.8 数字格式

必须作为横切任务处理，否则同一指标在 KPI、表格、图表、AI 上下文中会出现不同单位。

| 场景 | 当前问题 | 建议 |

## 五、智能助手输出格式（保留原分析并校正）

该项不是 5.1～5.9 的页面改动核心，但与“支持智能分析”的验收体验强相关，建议继续保留在整改计划中。

### 当前状态

- `FinancialAssistantPanel.vue` 仍用 `{{ msg.content }}` 纯文本渲染；
- `frontend\package.json` 未安装 `marked`；
- `_build_chat_prompt()` 未明确要求分段、换行、标题、列表；
- 流式接口实际使用 `_build_chat_prompt()` + RAG 规则，非流式接口另有 prompt 拼接，两个路径需同时处理。

### 建议输出格式要求

后端 prompt 增加：

```text
输出格式要求：
1. 使用中文数字标题分段（一、二、三...）
2. 每个标题下按行列出指标，格式为“指标名：数值（对比信息）”
3. 异常、原因、建议单独分段
4. 不要把所有内容挤在一段
```

前端两种可选方案：

| 方案 | 优点 | 风险 |
|---|---|---|
| `marked` + `v-html` | Markdown 表现好 | 必须做 XSS 清洗；不能直接渲染未净化 HTML |
| 纯文本保留换行 + 简单样式 | 安全简单 | 标题/列表表现弱 |

若使用 `marked`，应同时加入 DOMPurify 或限制/净化 HTML，不建议只用 `v-html`。

## 六、建议实施优先级

1. **统一期间维度模型**：先定义 `monthly/quarterly/cumulative/custom`，否则 5.2～5.6 都会反复返工。
2. **修正 5.1/5.7 毛利率拆解算法**：后端、前端类型、AI 知识库同步。
3. **调整 5.3 变动分析页面**：把算法输出落成 4 卡 + 明细表。
4. **修 5.2 总览趋势和展示细节**：尤其是趋势横轴、次坐标轴、毛利率 pp 后缀。
5. **部门/产品页复用公共期间筛选组件**：避免每页各写一套季度/YTD逻辑。
6. **统一数字格式 5.8**：抽工具函数并逐页替换。
7. **落地 5.9 客户分析入口**：在算法和期间口径稳定后做独立页面。
8. **优化智能助手输出格式**：同步 prompt 与前端安全渲染。

| 验收项 | 验收方式 |
